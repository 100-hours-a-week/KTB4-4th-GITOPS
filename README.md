# Need U V3 GitOps

Need U V3의 Kubernetes 배포 상태를 Git으로 관리합니다. Argo CD가 이 저장소를 읽어 Dev·Production EKS에 반영합니다.

## 책임 범위

| 저장소 | 관리 대상 |
| --- | --- |
| [CLOUD](https://github.com/100-hours-a-week/KTB4-4th-CLOUD) | Terraform: VPC, EKS, Node Group, AWS IAM, Pod Identity Association, RDS, Valkey 등 AWS 인프라 |
| GitOps | Kubernetes Namespace, RBAC, ServiceAccount, Helm Chart, 환경별 Values, Argo CD Application, Ingress, NetworkPolicy |
| FE·BE·AI | 애플리케이션 코드와 Container Image |

AWS IAM Role과 Kubernetes ServiceAccount는 서로 다른 리소스입니다. 이름과 Namespace를 두 저장소에서 맞추되, 같은 리소스를 Terraform과 Argo CD가 중복 관리하지 않습니다. Argo CD 최초 설치와 `argocd` Namespace 생성은 부트스트랩 작업입니다.

## 배포 흐름

```text
FE·BE·AI 저장소 → CI에서 Image Build·ECR Push
→ 이 저장소의 환경별 Image Digest 변경 PR·승인
→ Argo CD Sync → EKS
```

Production 배포는 승인된 Git 변경으로만 진행합니다. CI는 Production EKS에 직접 `kubectl apply`하지 않습니다.

## 디렉터리

```text
charts/application/       공통 Workload Helm Chart
environments/dev/         Dev Workload Values
platform/namespaces/      Namespace 정의
platform/serviceaccounts/ ServiceAccount 권한 설계
```

Dev Workload Values는 배포 전 초안이며, Image Digest·Secret·Probe·자원 요청량을 확인한 뒤 활성화합니다. Dev Namespace의 자원 정책은 `platform/namespaces/dev/`에 둡니다. Namespace와 자원 정책을 Workload보다 먼저 동기화합니다. RBAC 주체와 권한은 인증 방식이 정해진 뒤 구성합니다.

## 로컬 검증

```bash
helm lint charts/application
helm template frontend charts/application -f environments/dev/frontend.yaml > /dev/null
helm template auth-api charts/application -f environments/dev/backend-image.yaml -f environments/dev/auth-api.yaml > /dev/null
```

Backend API는 공통 Image를 사용하므로 `backend-image.yaml`을 먼저, 서비스별 Values를 뒤에 전달합니다. 공통 Chart를 변경하면 Dev와 Production Values를 모두 렌더링해 영향을 확인합니다. Secret 원문은 Git·Helm Values에 넣지 않습니다.

## 협업 규칙

- 브랜치: `<종류>/<환경>-<작업>-<이슈번호>` (예: `chore/dev-gitops-bootstrap-1`)
- 종류: `feat`, `fix`, `chore`, `docs`; 환경: `dev`, `prod`, `common`
- `main`에는 PR로만 병합합니다. Production Values와 공통 Chart 변경은 플랫폼 팀 리뷰를 받습니다.
- 이슈와 PR은 `.github/` 템플릿을 사용합니다. PR에는 변경 환경, Argo CD Sync 영향, 검증 결과를 기록합니다.
